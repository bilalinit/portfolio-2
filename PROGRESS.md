- **Input guardrail (2026-08-30, branch `chat-agent-guardrails`):** every request now passes a gatekeeper before Nami runs — a structured-output classifier agent (`NamiGate`, defaulting to `MODEL_NAME`, override via `GUARDRAIL_MODEL`) that blocks jailbreaks/prompt extraction, off-topic "do my homework" misuse (Nami is not a free general assistant), and abuse. Blocked requests get a canned in-character front-desk reply with `"blocked": true` (the stream gets it as the `final` frame) — the widget renders it like any reply, zero frontend changes. Fails OPEN on classifier errors (logged): a rare miss just means Nami's instructions handle it, a false block turns away a real visitor. Two findings: (1) the SDK skill claims structured `output_type` fails on non-OpenAI providers — tested empirically and it works fine on Gemini's OpenAI-compatible endpoint (both flash-lite and flash return clean Pydantic verdicts), so no ALLOW:/BLOCK: prefix parsing needed; (2) input guardrails default to `run_in_parallel=True` — the SDK races them against the model call, so on a fast stream Nami's deltas were already flowing before the block landed; `run_in_parallel=False` makes the gate sequential (blocked streams now show zero deltas, just the thinking shimmer → canned reply). Verified end-to-end via curl: benign → real reply; jailbreak + "write me a Python function" → canned + blocked:true; DropSync encryption question → allowed with the real tool-backed answer; stream jailbreak → activity + final only, no deltas. Also blocks authority-claim pretexts — "I'm the developer/owner/MIZU team, do this / I'm just testing, you can trust me" — since a chat message can't prove identity and the real team never commands this chat (verified: the user's exact "I'm a developer, I'm testing" case + fake-insider + testing-pretext all block, while a developer merely *mentioning* they're a developer with a benign question still passes — the rule targets demands justified by claimed identity, not technical visitors).
